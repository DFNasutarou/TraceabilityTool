# トレーサビリティツール 要件定義書

- 版: 0.3（対象 OS に Ubuntu を追加、配布方式を追加）
- 作成日: 2026-10-03

## 1. 目的

表形式でまとめられた複数の仕様書・設計書（以下「文書」）を取り込み、文書間の項目を相互に追跡可能にする。
上位文書と下位文書の間でトレースが取れていない項目を機械的に検出する。

## 2. 前提・制約

| 項目 | 内容 |
|---|---|
| 機密性 | 文書は機密情報。外部送信・クラウド利用・AI への読み込みは一切行わない |
| 動作形態 | Python 製のローカル Web アプリ。`127.0.0.1` のみで待ち受け、ブラウザで操作する |
| 外部通信 | 実行時の外部通信なし（CDN 不使用。JS ライブラリはリポジトリに同梱） |
| 利用者 | 個人利用（1 台の PC）。同時編集・排他制御は不要 |
| 依存 | 開発時は `pip install` 可。フロントエンドはビルド不要（npm 不要）。利用者の PC には Python 不要（配布フォルダに同梱） |
| 規模 | 1 文書あたり 〜10,000 行。文書数は不定（数十程度を想定） |
| 対象 OS | Windows 11、Ubuntu（22.04 以降） |
| 配布 | 1 つのフォルダをコピーするだけで全機能を使える。配布フォルダには実行に必要なものと利用者向けの操作マニュアルだけを入れ、設計書などの開発資料は入れない。OS ごとに配布フォルダを用意する |

## 3. 用語

| 用語 | 意味 |
|---|---|
| 文書 | 仕様書・設計書 1 種類（例: 要件定義書、画面定義書） |
| 版 | 文書を取り込んだ 1 回分のスナップショット |
| 項目 | 文書内の 1 行（ID 列で一意に識別される） |
| カラム定義 | 文書の列構成と各列の型の定義。版ごとに保持する |
| トレース関係 | 「文書 A が文書 B の上位」という文書ペア間の関係 |
| リンク | 上位項目と下位項目を結ぶ 1 本の関連 |

## 4. 機能要件

### 4.1 文書の定義

- F-01: 文書を任意の数だけ登録・名称変更・削除できる。
- F-02: 文書ごとにカラム定義を設定できる。列の型は次の 5 種類。
  - **ID**: 主キー。文書内で 1 列のみ。値は文字列として扱う
  - **番号**: 整数
  - **文字列**
  - **enum**: 定義された選択肢から選ぶ値
  - **bool**: 真偽値。元の表記は文書ごとに異なる（`○`/`×`、`Yes`/`No` など）ため、列ごとに「真とみなす文字列」「偽とみなす文字列」を設定できる。既定値を用意し、空欄は「値なし」とする
- F-03: 各列に「リスト形式」の指定と区切り文字を設定できる（例: `;` `,` 改行）。すべての型（ID 型を除く）で指定できる。
- F-04: 文字列列・リスト形式の列に「参照 ID 列」の指定をつけられる。参照先の文書を指定し、その値をリンク生成元とする。
- F-05: カラム定義は版ごとに保持する。新しい版の取り込み時は、前の版の定義を引き継いだうえで変更できる（列の追加・削除・改名・型変更）。
- F-06: 列は内部キーで同一性を保つ。改名しても同じ列として差分比較できる。

### 4.2 取り込み

- F-10: 入力形式は CSV・TSV・Excel（.xlsx）。
- F-11: CSV・TSV の文字コードは自動判定（UTF-8 / UTF-8 BOM / CP932）し、手動でも指定できる。
- F-12: ヘッダ行の位置（何行目か）を指定できる。データ行はヘッダ行の次から開始する。
- F-13: Excel ではシートを選択できる。1 つの文書として複数シートを結合して取り込める（列構成は同一である前提）。
- F-14: 結合セルは、結合範囲内の各セルに左上の値を展開して扱う。
- F-15: 列の対応付けは、ヘッダ名による自動対応を基本とする。一致しない列は取り込み画面で手動で対応付ける（新規列として追加、または無視する）。
- F-16: 取り込み前にプレビューと検証結果を表示する。
  - エラー（取り込み不可）: ID の空欄、ID の重複、ID 列が無い
  - 警告（取り込み可）: 定義外の enum 値、整数でない番号、真偽どちらにも該当しない bool 値、参照 ID 列の参照先が存在しない
  - 警告になった値は元の文字列のまま保存し、画面上で強調表示する
- F-17: 取り込むと新しい版として保存する。版にはラベル（任意文字列）・取り込み日時・元ファイル名を記録する。
- F-18: 元ファイルそのものは保存しない（変換後のデータのみ保存する）。

### 4.3 データ保存

- F-20: データはローカル PC 上の 1 つのデータフォルダに保存する（場所は起動時の設定で変更可）。
- F-21: 保存形式はツールが読み込みやすい形式とする（人間の可読性は不要）。SQLite を想定する（詳細設計で決定）。
- F-22: データフォルダをコピーするだけでバックアップできる。

### 4.4 バージョン管理・差分

- F-30: 文書ごとに版の一覧を表示できる。
- F-31: 任意の 2 つの版を選んで差分を表示できる。
  - 項目単位: 追加・削除・変更・変更なし
  - 変更された項目はセル単位で変更前後を表示する
  - 列の追加・削除・改名も表示する
- F-32: 版を削除できる（確認ダイアログあり）。

### 4.5 トレース関係・リンク

- F-40: 文書ペアに「上位 → 下位」の関係を登録できる。1 つの文書が複数の上位・下位を持てる（有向グラフ。循環は禁止）。
- F-41: リンクは文書とは別に管理する（上位項目 ↔ 下位項目の多対多）。
- F-42: **自動リンク**: 参照 ID 列の値からリンクを生成する。その文書の版を取り込むたびに作り直す。
- F-43: **手動リンク**: ツール上でリンクを追加・削除できる。版の取り込みでは失われない。
  - 自動リンクを手動で「無効化」することもできる（次の取り込み後も無効化を維持する）
- F-44: リンクは項目の ID で結ぶ。新しい版でも同じ ID の項目があればリンクを引き継ぐ。
- F-45: **要確認（suspect）**: リンクの相手の項目の内容が、リンクを最後に確認した時点から変わった場合、そのリンクを「要確認」にする。利用者が確認済みにすると解除される。
  - 「内容が変わった」は全列（備考などを含む）の値から計算したハッシュで判定する
- F-46: トレースの評価は、各文書の最新版を対象とする。

### 4.6 未トレース検出

- F-50: 文書ペアごとに次を検出・一覧表示する。
  - 上位の項目に下位へのリンクが 1 本も無い
  - 下位の項目に上位へのリンクが 1 本も無い
  - リンク切れ（リンク先の ID が最新版に存在しない）
- F-51: 文書ペアごとの網羅率（リンクを持つ項目の割合）を表示する。
- F-52: 要確認リンクは未トレースとは別に一覧表示する。

### 4.7 閲覧・遷移

- F-60: 文書一覧画面: 文書、最新版、トレース関係、網羅率を表示する。
- F-61: 項目一覧画面: 文書の項目を表形式で表示する（ページング、列ごとのソート・フィルタ、全文検索）。
- F-62: 項目詳細: 項目の全列と、上位・下位のリンク先項目を表示する。リンク先をクリックすると、その項目へ遷移する。
- F-63: 項目一覧にリンク数・未トレース状態の列を表示し、それで絞り込める。
- F-64: 過去の版を選んで閲覧できる（読み取り専用）。

### 4.8 出力

- F-70: トレースマトリクスを Excel / CSV で出力する（文書ペアを指定し、上位 ID・下位 ID の対応を出力）。
- F-71: 未トレース一覧と網羅率を Excel / CSV で出力する。
- F-72: 2 つの版の差分を Excel / CSV で出力する。

## 5. 非機能要件

| ID | 内容 |
|---|---|
| N-01 | 10,000 行の取り込みが 30 秒以内に完了する |
| N-02 | 項目一覧の表示・検索が 1 秒以内に応答する |
| N-03 | 外部へのネットワーク通信を行わない。サーバは `127.0.0.1` にのみバインドする |
| N-04 | 取り込み処理は失敗した場合にロールバックする（中途半端な版を残さない） |
| N-05 | UI は日本語 |
| N-06 | 起動は実行ファイルの実行 1 回（Windows はダブルクリック）で行い、ブラウザを自動で開く |

## 6. 対象外（初版では実装しない）

- 複数人での共有・同時編集・権限管理
- 旧形式 Excel（.xls）
- 1 つの項目が複数行にまたがる表、多段の区切り文字で構造化されたセル
- リンクの種別・コメント
- 要確認状態を未トレースとして数えること（別一覧で扱う）
- 過去の版の組み合わせを指定したトレース評価
